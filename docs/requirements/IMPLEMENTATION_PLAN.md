## 0. 执行规则

1. 按 P00 → P13 顺序执行，**每次只提交一条**提示词。
2. 上一步通过验收后方可进入下一步。
3. 每条开始时必须先读取仓库最新状态（README、docs、Git 状态、相关源码）。
4. 不得重建已有工程、覆盖已有文件、重构无关模块、删除用户数据。
5. 所有 Mock 必须显著标识。
6. 每轮必须实际执行可用构建/测试，并输出命令与结果；不能运行的测试须说明原因与人工步骤。

## 3. 各阶段详情

### P00｜项目需求基线初始化 ✅ 本轮执行

- **目标**：把已确认需求转化为可执行工程基线。
- **交付物**：
  - `docs/requirements/PRODUCT_BASELINE.md`
  - `docs/requirements/ROLE_PERMISSION_MATRIX.md`
  - `docs/requirements/PAGE_INDEX.md`
  - `docs/requirements/IMPLEMENTATION_PLAN.md`
  - `docs/api/CONTRACT_DRAFT.md`
- **明确不做**：不创建 Android / Web 工程；不生成业务页面；不编写模拟 AI 识别；不删除已有文件；不改变技术架构。
- **验收标准**：文档包含三端权限矩阵、全部页面索引（E01–E15 / F01–F12 / A01–A10）、已知系统约束和验收标准；未破坏已有代码。
- **备注**：本轮工作区为空，属从零建立文档，无覆盖风险。

---

### P01｜初始化仓库与基础工程

- **目标**：建立可编译的 Android 和 Web 双工程。
- **范围**：
  - `apps/android`：Kotlin + Jetpack Compose
  - `apps/admin-web`：Vue 3 + TypeScript + Vite + Element Plus
  - 统一 `.gitignore` 与 `README.md`
- **禁止**：暂不加入 MediaProjection、AI 模型或业务登录。
- **验收**：两个工程可启动/构建；Git 忽略规则有效；无不必要依赖；留存 Android Gradle 构建与 Web `typecheck`/`build` 日志。
- **已知限制**：若本机 Android SDK 不可用，须说明限制与替代验证方式，不得宣称构建通过。
- **依赖**：P00。

---

### P02｜统一视觉系统与通用 UI 组件

- **目标**：固定三端视觉规范，建立组件复用基础。
- **Design Tokens**：主色 `#174A71`、交互色 `#176497`；安全 `#25845E`、提醒 `#D8A03A`、危险 `#C83C3C`。
- **老人端约束**：正文优先 18sp、按钮 ≥56dp、交互热区 ≥48dp、支持系统字体放大。
- **Android 组件**：`PrimaryButton`、`StatusCard`、`RiskBadge`、`EmptyState`、`ErrorState`、`LoadingState`。
- **Web 组件**：通用页标题、筛选区、数据表空态、确认弹窗。
- **要求**：提供每个组件的展示页或预览；禁止直接堆满所有业务页面。
- **验收**：Tokens 统一；组件无明显溢出；字号放大情况下基本可操作。
- **依赖**：P01。

---

### P03｜角色路由与通用登录骨架

- **目标**：一个 App 下分离老人 / 家属导航。
- **范围**：
  - Android 角色模型 `Elder` / `Family`（可支持多角色）。
  - Navigation Compose：老人底栏「守护 / 记录 / 我的」；家属底栏「家庭 / 风险 / 协同 / 我的」。
  - 清楚标记的**本地模拟登录**与角色切换，仅作前端测试。
  - 首次引导页（E01）与登录空态（E02）。
  - 管理端登录占位页、左侧 10 个一级菜单与动态路由，不实现真实鉴权。
- **禁止**：不得把服务端授权与真实登录写成已完成。
- **验收**：角色切换及路由正常；重启后本地状态一致；页面占位无崩溃。
- **依赖**：P02。

---

### P04｜老人端守护首页与授权引导

- **目标**：实现老人使用链路的主要界面。
- **范围**：E03 守护首页、E04 授权说明、E05 运行状态、E13 守护设置、E14 隐私与授权。
- **状态模型**：`GuardState = OFF / REQUESTING / RUNNING / DEGRADED / STOPPED / ERROR`。
- **实现方式**：当前用 `FakeGuardService` 接口驱动 UI；界面必须明显显示"模拟守护"。
- **要求**：开始、停止、权限失效、音频不可用等状态均可演示；不得伪造系统级采集已成功；停止入口必须容易找到。
- **验收**：所有守护状态可测试；按钮有实际状态行为；未接入真实采集时有清晰标识。
- **依赖**：P03。

---

### P05｜独立 Android 屏幕采集可行性验证

- **目标**：优先消除跨应用采集风险。
- **范围**：新增独立 PoC 或 `guard-engine` 模块；使用 Android 官方 `MediaProjection`，按目标 SDK 要求创建合规前台服务。
- **要求**：
  - 必须由用户主动开始并通过系统授权。
  - 提供停止与权限撤销处理。
  - 仅在本地处理授权测试画面；先不上传、不存长期录像、不获取其他 App 私有接口。
  - 不申请不必要的无障碍权限。
- **报告内容**：测试设备、Android 版本、授权行为、采集成功条件、受保护内容/音频限制。
- **验收**：在真实 Android 设备记录启动 / 停止 / 撤销 / 锁屏测试；明确无法获取的场景。
- **依赖**：P01。**可与 P04 并行**。

---

### P06｜风险事件列表、详情与预警组件

- **目标**：打通老人端风险发现到解释的 UI 闭环。
- **范围**：E06–E08。
  - E06：风险轻量提醒与高风险提醒。
  - E07：类型、线索、可用模态、证据摘要、处理建议、"信息不足"状态。
  - E08：Room 存储本地风险记录，支持筛选、删除和清空。
- **实现方式**：通过 `RiskEventRepository` 的 Fake 实现注入示例事件，所有示例显著标记。
- **禁止**：不以模型分数冒充诈骗概率；无证据时不得显示"已确认安全"。
- **验收**：事件从模拟引擎到本地记录完整闭环；删除生效；列表无数据时有空态。
- **依赖**：P04。

---

### P07｜家属绑定与授权管理页面

- **目标**：实现家庭关系和隐私交互。
- **范围**：F02、F04、F09，以及老人端家属绑定入口。
- **状态**：邀请 / 接受 / 拒绝 / 解除绑定需有清晰状态。
- **授权模型**：分为「按事件分享」与「明确事先授权的范围设置」，**默认关闭**。
- **实现方式**：`FamilyRepository` 模拟正常、等待确认、过期、撤销场景。
- **要求**：UI 说明家属不能查看原始视频和实时屏幕；不得单凭前端状态认定已授权。
- **验收**：双方确认流程完整；撤销状态可见；授权默认关闭。
- **依赖**：P03。

---

### P08｜家属事件与协同处理页面

- **目标**：实现家属核心业务闭环。
- **范围**：F03、F05–F08、F11。
  - F03 家庭首页；F05 共享事件列表；F06 事件详情；F07 联系老人入口；F08 处理详情。
  - 协同状态：待查看 / 已查看 / 已联系 / 核实中 / 已协助处理 / 无法核实。
- **要求**：模拟数据仅允许出现授权共享事件；保留离线和消息延迟展示状态；处理状态与 AI 原始风险等级分别管理，家属不能改写模型原始结论。
- **验收**：家庭首页与事件处理交互流通畅；无授权时空态正确。
- **依赖**：P07。

---

### P09｜管理后台工作台与通用数据管理

- **目标**：建立可扩展的管理端操作体验。
- **范围**：A01–A03、A10 的前端骨架。
  - 顶部栏、左侧导航、工作台、用户/设备表格、管理员与权限设置占位。
  - 统一表格、搜索、筛选、分页、详情抽屉。
  - 每页包含 Loading / Empty / Error 状态。
- **要求**：统计卡片使用标注"演示数据"的 Mock，不虚构真实运营指标；API 调用统一放 `src/api`，视图不直接拼接请求。
- **验收**：十个一级菜单可访问；核心表格可筛选；生产构建通过。
- **依赖**：P01、P02。

---

### P10｜数据集管理完整前端

- **目标**：优先建设团队核心研发后台。
- **范围**：A04 —— 数据集列表、上传向导、来源与许可登记、标注工作台、质检、去重、数据拆分、版本管理。
- **数据要求**：每个样本记录 source/license、风险类别、证据位置、审核状态；标注支持多标签。
- **合规要求**：数据样例必须为自制或明确许可的演示素材；不得自动爬取短视频平台，不得把私人屏幕内容当训练数据。
- **接口**：先对接 Mock Repository 并定义 API 契约。
- **验收**：所有状态与校验完整；没有许可信息的样本不能标记为可正式训练。
- **依赖**：P09。

---

### P11｜模型训练任务与结果页面

- **目标**：管理团队自主训练的可追踪工作流。
- **范围**：A05 —— 任务列表、创建表单（模型/数据版本/参数）、任务详情、日志查看、指标图表、失败重试状态。
- **架构约束**：训练是独立 Python Worker 执行，不在浏览器运行。
- **要求**：未接真实 Worker 时只显示"模拟任务"，不能假装训练成功；针对 `pending / running / succeeded / failed / canceled` 做状态组件；先交付前端与 OpenAPI 请求类型。
- **验收**：可展示真实/模拟来源区分；训练日志和评估指标有独立位置；Web 构建通过。
- **依赖**：P10。

---

### P12｜模型版本与发布流程页面

- **目标**：支持受控发布、回滚与端侧适配。
- **范围**：A06 —— 模型仓库、版本详情、测试/审核、量化信息、兼容性、发布审批、撤回与回滚界面。
- **版本对象必备字段**：`modelVersion`、`datasetVersion`、`fileHash`、`signature`、`runtimeCompatibility`、`evaluationSummary`、`releaseStatus`。
- **要求**：发布按钮只有具备权限且满足审核条件才可用；必须采用服务端二次校验；UI 展示审核记录和操作人。
- **验收**：发布前置条件、失败回滚和模型文件校验信息界面齐备。
- **依赖**：P11。

---

### P13｜整体验收、契约对接与交付审计

- **目标**：完成可运行前端基线和真实联调记录。
- **范围**：
  - 审查 E/F/A 页面索引，输出页面覆盖矩阵、未实现清单和 Mock 清单。
  - 接入现有自建业务后端；实现服务端授权校验错误态、断网重试与撤销共享。
  - 检查 Android Gradle 构建、Web `typecheck`/`build`、无障碍文字缩放、空态/错误态、权限边界。
- **禁止**：不得伪造测试；不能运行的测试须列出原因和人工执行步骤。
- **产出**：APK / 前端构建目录（如可构建）、验收报告、Git 提交摘要。
- **验收**：所有 P0 页面通过功能与权限验收；尚未联调和未验证能力明确列为风险。
- **依赖**：P04–P12。

## 6. 风险登记

| # | 风险 | 影响阶段 | 应对 |
|---|---|---|---|
| R1 | 跨应用内容无法采集（受保护页面、DRM、音频源策略） | P05、M5 | 尽早真机 PoC；明确降级提示；不承诺全量覆盖 |
| R2 | `AudioPlaybackCapture` 受策略限制导致音频缺失 | P05、P06 | 设计"降级运行"状态并在 UI 明示 |
| R3 | 端侧模型体积/算力不足，老人机性能受限 | M5 | 量化、兼容性矩阵、A03 设备管理前置 |
| R4 | 训练执行器未就绪，管理端只能展示模拟任务 | P11、M4 | Mock 强标识；不得标记"训练可用" |
| R5 | 授权撤销后缓存事件仍可见（越权） | P08、P13 | 服务端对象级校验 + 客户端撤销即清缓存 |
| R6 | Android SDK 环境缺失导致无法本地验证构建 | P01 | 记录限制与替代验证方式，不宣称通过 |
| R7 | 页面优先级缺失导致排期争议 | 全程 | 补齐 F/A 优先级（见待确认事项） |

## 7. 变更管理

V1.3 为前端开发基线。以下变更属于**架构级变更**，须团队评审并同步更新需求文档、权限矩阵与接口契约，不得由 AI 编程工具自行决定：

- 新增角色
- 扩大数据共享范围
- 改为云端 AI 识别
- 引入短视频平台接口
