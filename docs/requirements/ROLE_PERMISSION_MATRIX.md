**图例：**

## 2. 数据主体与授权链

核心原则：**老人是唯一授权主体**。家属与管理员的一切数据可见性，均以老人签发的有效 `ConsentRecord` 为前提。

```
老人（唯一授权主体）
  ├── 系统屏幕采集授权 ──→ 仅本机，不可远程开启
  ├── 事件共享授权 ──────→ 指定家属 / 指定事件范围 / 有效期
  └── 撤销 ─────────────→ 立即生效，服务端同步失效
```

不允许的授权路径：

- 家属代替老人授权 ❌
- 管理员代替老人授权 ❌
- 后台远程开启老人屏幕采集 ❌
- "看见菜单"被当作权限凭据 ❌（V1.3 第 2.3 节明确）

## 4. 对象级访问控制规则

以下为服务端必须执行的判定，不依赖前端菜单显隐：

| 规则 | 描述 |
|---|---|
| R1 | 家属查询任一 `RiskEvent` 前，须校验存在覆盖该 `eventId` 的有效 `ConsentRecord` |
| R2 | `ConsentRecord` 撤销后，家属对相关事件的访问立即失效（含已缓存的列表项） |
| R3 | 管理端任何查询默认返回脱敏聚合结果，不下发原始证据 |
| R4 | 任何角色均无接口可读取原始屏幕录像 |
| R5 | 老人本人的本地记录，仅在本机可读，不经业务后端存储原文 |
| R6 | 越权请求返回 403 且写入审计日志 |

> 【待与 V1.3 原文核对】R1–R6 为 P00 推导，V1.3 第 05 章有原则表述但无逐条编号，需评审确认后固化为契约条款。

## 5. 权限相关的 UI 责任

| 场景 | 必须的 UI 表达 |
|---|---|
| 家属未获授权 | 空态说明"当前没有可查看的事件"，不显示伪造数据 |
| 共享已撤销 | 明确提示"老人已撤销对您的共享" |
| 管理端无发布权限 | 按钮禁用 + 说明原因，不只靠灰化 |
| 任何 Mock 数据 | 页面上显著标识"演示数据" |
| 模拟守护状态 | 明显显示"模拟守护"，不得暗示真实采集成功 |
