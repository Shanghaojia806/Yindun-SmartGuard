## 1. 产品定位与目标

面向老年群体的短视频多模态反诈交互系统。核心识别能力运行在老人手机本地，识别短视频场景中的诈骗风险并给出可理解的提示与解释。

三类使用主体的目标：

- **老人**：授权守护、接收风险提醒、理解风险原因、留痕与回顾风险记录。
- **家属**：在获得老人授权的前提下，接收风险事件、协同处理，不越权查看老人隐私。
- **研发/运营团队**：在管理后台完成数据集标注、训练任务、评估、模型版本与发布管理。

### 1.1 产品价值主张

【待与 V1.3 原文核对】V1.3 第 1.1 节仅说明目标，未逐条列出价值主张措辞。以下为待评审条目：

1. 老人侧"看得懂"的风险解释优先于风险分数展示。
2. 隐私默认最小化：默认不采集、不共享原始内容。
3. 家属协同而非监控：家属看到的是事件与处理状态，不是实时屏幕。
4. 研发过程可追溯：数据、训练、模型版本全链路留痕。

## 2. 明确不做（范围红线）

以下条目直接取自 V1.3 第 1.2 节，属于架构级红线，任何阶段不得违反：

| # | 不做的事 |
|---|---|
| N1 | 不要求老人逐条上传视频作为核心使用路径；仅作为兼容性不足时的可选辅助入口 |

| N5 | 不把演示 Mock 数据、模拟训练进度、虚构识别结果当作真实成果 |

## 3. 技术架构基线

### 3.1 三端 + 一后端的整体结构

```
┌──────────────────────────────────────────────────────────┐
│  老人端 / 家属端：同一个原生 Android App（Kotlin + Compose） │
│  角色路由分离；端侧 Guard Engine 本地推理                    │
└───────────────┬──────────────────────────────────────────┘
                │ HTTPS（事件摘要 / 授权 / 协同状态，非原始录像）
┌───────────────▼──────────────────────────────────────────┐
│  业务后端：自建 FastAPI                                    │
│  身份、家庭绑定、授权共享、模型/内容分发、管理业务            │
│  不承担核心云端诈骗识别                                     │
└───────────────▲──────────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────────┐
│  管理后台：Vue 3 + TypeScript + Vite + Element Plus         │
│  数据集 / 训练任务 / 模型版本与发布 / 规则 / 知识库 / 系统管理 │
└──────────────────────────────────────────────────────────┘
```

### 3.2 技术栈（V1.3 第 4.1 节）

| 工程 | 技术与职责 |
|---|---|
| Android | Kotlin、Compose、MVVM、Navigation、Room、DataStore、Coroutines/Flow；MediaProjection 服务与推理引擎各自独立模块 |
| Web 后台 | Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router、ECharts |
| 业务接口 | 自建 FastAPI；身份、绑定、共享、模型发布、管理业务；不负责核心云端诈骗识别 |
| AI 训练 | Python、PyTorch；训练执行器独立；模型导出、端侧推理兼容性测试 |

### 3.3 仓库结构基线（V1.3 第 4.2 节）

```
silver-shield/
├── apps/android            # 老人/家属同一个 App
├── apps/admin-web          # Vue3 管理后台
├── services/business-api   # FastAPI 业务后端
├── ml/
│   ├── datasets
│   ├── training
│   ├── evaluation
│   └── export
└── docs/
    ├── requirements
    ├── ui
    ├── api
    └── testing
```

> 说明：本地工作区根目录当前命名为 `银盾智鉴`，与文档中 `silver-shield` 为同一逻辑仓库。【待与 V1.3 原文核对】仓库根目录最终命名。

### 3.4 前端分层与解耦（V1.3 第 4.3 节）

强制分层：`UI → ViewModel/Store → Repository/API Gateway → 真实接口 或 Mock Adapter`

强制约束：

- 不得在 Composable 页面中直接执行录屏、网络请求或模型调用。
- 必须使用抽象接口：`GuardEngine`、`RiskEventRepository`、`FamilyConsentRepository`、`TrainingTaskRepository`。
- Web 端 API 调用统一收敛在 `src/api`，视图层不直接拼接请求。

## 4. 核心业务原则

| 编号 | 原则 | 来源 |
|---|---|---|
| B1 | 老人必须主动授权屏幕采集；每次新会话按系统版本要求取得用户同意 | V1.3 第 01、05 章 |
| B2 | 家属仅可查看老人授权共享的风险事件与协同处理状态 | V1.3 第 01 章 |
| B3 | 默认不上传原始屏幕录像，仅经授权发送事件摘要与处理状态 | V1.3 第 05 章 |
| B4 | 不依赖短视频平台私有接口或专用接口 | V1.3 第 01 章 |
| B5 | 管理端负责数据集、训练任务、模型版本和发布管理 | V1.3 第 02 章 |
| B6 | 模拟数据与真实功能必须严格区分，所有 Mock 必须显著标识 | V1.3 第 05 章 |
| B7 | 授权由老人发起和撤销；家属与后台均不能远程开启采集 | V1.3 第 05 章 |
| B8 | 核心 AI 推理在老人手机端本地执行，不调用商业识别 API | V1.3 第 01 章 |

### 4.1 守护状态模型

V1.3 提示词 04 定义守护状态为：`GuardState = OFF / REQUESTING / RUNNING / DEGRADED / STOPPED / ERROR`

页面侧还需覆盖 V1.3 第 3.2 节列出的人读状态：未开启、授权中、运行中、降级运行、已停止、授权失效。

【待与 V1.3 原文核对】`ERROR` 与"授权失效"是否为同一枚举值，或后者由 `ERROR` 携带原因码表达。

## 7. 非功能要求与质量门槛

### 7.1 隐私与权限

- MediaProjection 每个新会话按系统版本要求取得用户同意；禁止承诺永久静默录屏。
- 跨应用内容可采集性不保证；`AudioPlaybackCapture` 受音频源策略限制；无法获取时明确提示降级。
- 端侧默认不上传原始屏幕；仅经授权发送事件摘要与处理状态。
- 授权由老人发起和撤销；家属和后台均不能远程开启采集；服务端执行对象级访问控制。
- 本地风险记录支持查询、删除和清空；需设计离线/弱网/消息重复/撤销授权的处理方式。

### 7.2 视觉与无障碍（V1.3 第 03 章）

| 设计项 | 规范 |
|---|---|
| 主色 / 交互色 | `#174A71` / `#176497` |
| 语义色 | 安全 `#25845E`；提醒 `#D8A03A`；危险 `#C83C3C` |
| 老人端字号 | 正文优先 18sp 左右；支持系统字体缩放 |
| 触控区域 | 至少 48dp；主按钮建议 56–64dp 高 |
| 布局 | 老人端低密度；家属端信息卡片；后台信息表格与筛选 |
| 信息表达 | 等级同时显示文字与图标，避免仅靠颜色；风险概率未经校准不展示 |

### 7.3 页面状态完整性

每个取数页面必须具备 Loading / Success / Empty / Error 四态。守护模块必须额外具备：未开启、授权中、运行中、降级运行、已停止、授权失效。弱网时保持老人端本地守护能力。

### 7.4 验收门槛（V1.3 第 06 章）

| 阶段 | 主要内容 | 通过门槛 |
|---|---|---|
| M0 | 仓库初始化、需求与契约、Android 采集 PoC | Android/Web 可构建；真机授权采集验证记录 |
| M1 | 角色导航、设计系统与静态页面 | 三端核心页面可导航，空态/异常态完整 |
| M2 | 老人本地守护及风险事件 UI | 假引擎可切换；停止守护有效；Room 保存记录 |
| M3 | 家属绑定、授权事件同步 | 服务端授权校验、撤销、双向状态联调 |
| M4 | 后台数据/训练/模型管理 | 真实持久化与真实训练执行器/日志 |
| M5 | 自主模型端侧集成、测试验收 | 真机推理、误报/漏报评估、模型回滚 |

验收还需包含：构建、单元测试、无障碍与字体缩放、真机采集测试、数据越权测试、耗电/卡顿记录。
